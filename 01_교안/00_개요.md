# Private LLM Infra — 강의 개요 및 진행 시나리오

팀스파르타 AI 튜터 채용 시범강의(20분) 교안. 원본 문서(팀스파르타 튜1.docx)를 기준으로, 실제 강의처럼 진행할 수 있도록 도입-전개-정리 흐름과 발화 스크립트를 갖춘 교안으로 작성했다.

## 강의 개요

| 항목 | 내용 |
| --- | --- |
| 주제 | 클라우드 인프라 / Private LLM 서빙 / LLMOps |
| 목표 | Private LLM을 기업 환경에 배포할 때 필요한 기술 축을 이해한다 |
| 대상 | 대학교 IT 계열 전공자 |
| 구성 | 개념 설명 + 시연 |
| 분량 | 파트별 15~20분 (택 1 또는 전체) |

## 강의 핵심 내용

이번 강의에서는 Private LLM Infra를 다음 3개의 축으로 나누어 살펴본다.

| 축 | 의미 |
| --- | --- |
| 인프라 | 모델이 올라갈 실행 기반 |
| 서빙 | GPU 자원을 효율적으로 활용하는 추론 구조 |
| 운영 | 배포 이후 품질, 보안, 장애를 관리하는 체계 |

| 파트 | 제목 | 출처 |
| --- | --- | --- |
| PART 1 | 클라우드 인프라 | 팀스파르타 제공, 원본 유지 |
| PART 2 | Private LLM 서빙 | 학습목표 기반 신규 구성 |
| PART 3 | LLMOps | 학습목표 기반 신규 구성 |

## 시연 안내 (원본 문서 그대로)

- 시연은 본 교안을 화면 공유한 상태로, 실제 수강생에게 설명하듯 진행한다.
- 재구성하거나 추가 자료를 활용해도 무방하다 (자유 형식).
- 실제 시연에서는 모든 파트를 다뤄도, 일부만 설명해도 된다.
- 20분 분량에 맞춰 자유롭게 준비한다.
  - 예시 1: Part 2만 설명
  - 예시 2: Part 3만 설명
  - 예시 3: 모든 파트 설명
- Part 1은 팀스파르타에서 완성해 제공한 교안이다.
- Part 2, 3은 학습 목표를 바탕으로 강의를 직접 구성한다.
- 시연 후 질의응답(15분 내외)을 진행한다.

## 전체 진행 시나리오 (한 파트만 시연하는 경우, 약 20분)

| 단계 | 시간 | 내용 |
| --- | --- | --- |
| 오프닝 | 1분 | 자기소개 + 오늘 다룰 파트와 학습목표 안내 |
| 도입 | 1~2분 | 이번 파트가 왜 필요한지 동기 부여, 실무 맥락 연결 |
| 전개 | 12~15분 | 소단원별 개념 설명 + 비유 + 확인 질문 |
| 정리 | 2~3분 | 핵심 요약, 배운 내용 재확인, 질의응답 예고 |

## 오프닝 멘트 예시

"안녕하세요. 오늘은 Private LLM Infra 중에서 [파트명]을 함께 살펴보겠습니다. 이 파트가 끝나면 여러분은 [학습목표 한 줄 요약]을 할 수 있게 됩니다. 실무에서 실제로 어떤 고민을 할 때 이 내용이 쓰이는지부터 짚어보겠습니다."

## 파트 전환 멘트 예시 (모든 파트를 이어서 설명하는 경우)

- Part 1 → Part 2: "지금까지는 모델이 올라갈 자리, 즉 인프라를 봤습니다. 이제 그 인프라 위에서 모델이 실제로 요청에 응답할 때 무엇이 병목이 되는지, 서빙 관점으로 넘어가겠습니다."
- Part 2 → Part 3: "서빙까지 잘 만들었다면, 이제 남은 건 운영입니다. 배포한 뒤에 이 시스템이 잘 동작하는지 어떻게 확인하고, 어떻게 안전하게 지킬지를 살펴보겠습니다."

## 예상 질문 대비 (질의응답 15분 대비)

| 예상 질문 | 답변 방향 |
| --- | --- |
| On-prem과 Cloud 중 실무에서는 어떤 걸 더 많이 쓰나요? | 초기 스타트업은 Cloud로 시작해 트래픽이 커지면 Hybrid나 On-prem 비중을 늘리는 경우가 많다고 설명 |
| PagedAttention이 없으면 어떤 문제가 생기나요? | 메모리를 미리 넉넉히 예약해야 해서 동시 처리 가능한 요청 수가 줄어드는 점을 예시로 설명 |
| 가드레일을 다 넣으면 응답 속도가 느려지지 않나요? | 실제로 지연시간이 늘어날 수 있어, 리스크가 큰 영역부터 우선 적용하는 절충이 필요하다고 설명 |
